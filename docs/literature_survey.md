## 2. Summary of Possible Improvements (Team Contribution)

Based on the analysis of these 15 papers, existing systems generally fall into three categories: they are purely **theoretical**, highly **isolated to a single task** (e.g., just irrigation), or attempt **overly complex deep learning** approaches that aren't practical for standard open-field deployments.

To bridge these research gaps, our project will implement the following improvements:

1. **Holistic Twin Graph:** Instead of flat isolated sensors, we will use Azure Digital Twins (DTDL) to map the farm as a connected graph where soil moisture affects crop health dynamically across multiple zones.
2. **Twin-Augmented ML:** We will improve upon standard ML yield prediction (Paper 7) by feeding the ML model not just raw sensor data, but the *derived twin state* (e.g., computed zone stress indices).
3. **Cloud-Native Simplicity:** We will bypass the overly complex Fog/Edge architectures (Paper 2) by leveraging serverless Azure Functions and Stream Analytics to achieve scalability and automation directly in the cloud.
4. **Closed-Loop Serverless Automation:** We will design the backend to use Azure Functions for deterministic, closed-loop automation (addressing the gap in Paper 11 & 15). When the ML model predicts stress, the function automatically triggers a simulated response (e.g., irrigation adjustment) and updates the Digital Twin.
5. **Stateful Database Synchronization:** While Paper 12 uses time-series data passively, we will integrate Azure Cosmos DB with Azure Digital Twins so that historical trends actively define the current "state" of the virtual farm.
6. **Enterprise Security:** Bypassing custom security implementations (Paper 13), we will implement Microsoft Entra ID to secure our Azure App Service dashboard, ensuring robust role-based access for farmers and administrators.
